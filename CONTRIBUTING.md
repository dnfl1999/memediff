# Feedback and contributions

MemeDiff is a small, free, static GitHub activity tool. English and Korean reports are welcome.

- Start with the [usage guide](docs/GETTING_STARTED.md) and [FAQ](docs/FAQ.md).
- Search [existing issues](https://github.com/dnfl1999/memediff/issues) before filing a duplicate.
- Use [Bug report](https://github.com/dnfl1999/memediff/issues/new?template=bug_report.md) for reproducible failures, or [Usability feedback](https://github.com/dnfl1999/memediff/issues/new?template=feedback.md) for a real task that is difficult today. GitHub sign-in is needed to submit an issue; the app itself needs no login.
- Include the steps, expected/actual result, browser/device, selected period and observation time. Check attachments for private data. No credentials, seed phrases, cookies or private keys.

## Maintainer review checklist

1. Reproduce the report and separate API limits/outages from app defects.
2. Ask only for missing, non-sensitive details. Treat submitted links and files as untrusted.
3. Prefer an explanation, documentation fix or small repair over a new feature. Record the user problem and acceptance criteria before proposing substantial work.
4. For code changes, run unit tests and desktop/mobile Playwright, then verify Actions and deployed Pages. Keep live API checks separate from mocks; record skips honestly.
5. For documentation-only changes, review links, examples, privacy and consistency; do not deploy unchanged app code solely to refresh documentation.

This checklist is a process for future reports, not a scheduled monitoring job or a response-time promise. No issue has been created just to simulate user feedback. Feature suggestions are not commitments. Token trading, price targets, wallet transactions and artificial engagement are outside the software contribution scope.
